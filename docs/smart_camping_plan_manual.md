# Smart Camping Plan (Guided Journey) Core Engine Manual

라온아이의 핵심 가치인 '감성'과 '편안함'을 전달하기 위해, 사용자의 캠핑 일정을 기반으로 한 맞춤형 추천 여정(Guided Journey)을 구현하는 시스템의 개발 및 유지보수 매뉴얼입니다.

이 문서는 라온아이의 스마트 캠핑 플랜 기능 개발의 **단일 진실 공급원(SSOT)** 역할을 합니다. 다른 세션이나 개발자가 이 기능을 수정/확장할 때 반드시 이 문서를 기준으로 작업해야 합니다.

---

## 🏗️ 1. 아키텍처 철학 (Architecture Philosophy)

스마트 캠핑 플랜은 단순한 앱 기능이 아닌, 향후 B2B API 및 MCP(Model Context Protocol) 서버로 독립 가능한 **"헤드리스 지능형 엔진(Headless Intelligent Engine)"**으로 설계되었습니다.

1.  **UI/Logic Separation**: 추천 로직(`smartPlan.ts`)은 UI 컴포넌트와 완전히 분리되어 순수 데이터(JSON)만 반환합니다.
2.  **API Monetization Ready**: 생성된 데이터는 향후 외부 에이전트(LLM)가 즉시 이해하고 구매할 수 있도록 표준 스키마(Schema.org)와 출처(Provenance) 메타데이터를 포함합니다.
3.  **Zero-Cost High-Fidelity**: 유료 데이터(내비게이션 트래픽 등)와 LLM 다중 호출을 지양하고, 무료 공공데이터와 무료 API의 '볼륨 데이터'를 융합하여 비용 0원의 초정밀 팩트를 추출합니다.

---

## ⚙️ 2. 핵심 로직 파이프라인 (The 5-Step Pipeline)

사용자가 기기에서 "스마트 플랜 만들기"를 요청할 때부터 화면이 렌더링되기까지의 완벽한 흐름입니다.

### Step 1: Context Gathering (상황 수집)
- **위치/환경**: 사용자 기기의 GPS 위치(LBS), 선택된 캠핑장의 위치, 날짜, 해당 날짜의 날씨 및 온도.
- **캠퍼 페르소나**: 예약 정보(성인/미취학/초등/청소년 세분화) 및 DB 활동 로그(Record, 좋아요 등)에서 추출된 '태그 가중치(Tag Weight)'를 통해 동적 페르소나 문자열 생성 (예: "초등학생 자녀와 함께 조용한 자연 속 요리를 즐기는 캠퍼").

### Step 2: Zero-Cost High-Fidelity Filtering (0원 고품질 추출)
- 하단에 정의된 [3. High-Trust Indicators] 카테고리별 로직에 따라, 내부 DB에 사전 캐싱된 데이터를 1차 필터링하고 카카오 로컬 API(무료 쿼터)의 리뷰/블로그 '볼륨(개수)'으로 2차 교차 검증하여 최고의 팩트 후보군을 15개 내외로 생성합니다.

### Step 3: Circular Curated Pool (순환 풀링)
- Step 2에서 생성된 15개 내외의 최적 후보군 중, 매 요청 시 3~5개를 무작위(순환) 추출하여 화면의 식상함을 방지합니다.

### Step 4: AI Narration (단 1회 호출)
- Step 3에서 뽑힌 '완벽한 팩트 리스트 5개'와 Step 1의 '유저 Context'를 LLM(Gemini 1.5 Flash 등) 프롬프트에 단 1회 주입합니다.
- LLM은 이 팩트들을 바탕으로 "이 사람의 감성을 자극하는 스토리"를 작성합니다. (Stateless 방식)

### Step 5: Interactive UI Rendering (Citational UI)
- 화면 상단: LLM이 작성한 감성적인 가이드 서사.
- 화면 하단: 유저가 직접 상세 정보를 확인하고 다른 옵션으로 교체(슬롯 체인지)할 수 있는 팩트 카드 노출.

## 📌 3. 스마트 캠핑 플랜 15-Fact 추출 파이프라인 (Real-time Flow)

사용자가 '플랜 만들기' 버튼을 눌렀을 때 실행되는 내부 로직의 세부 명세입니다. (향후 수정/보완을 위한 Baseline)

1. **호출**: 프론트에서 `generatePersonalizedSmartPlan(userId, lat, lng, startDate, endDate)`를 찌릅니다.
2. **반경 검색 (DB)**: Supabase RPC (PostGIS) 함수가 호출되어 `캠핑장 반경 15km 이내`의 백년가게, 의료기관, 관광명소를 **단 50ms 만에** 조회하여 불러옵니다.
3. **가중치 로직 필터링 (Server-side)**:
   - *날씨 필터*: 예약 일정 중 비가 온다면 -> 야외 명소 가중치 삭감, "전골/국물류" 식당 가중치 상향.
   - *페르소나 필터*: DB에 저장된 유저 태그(예: `#키즈친화`, `#감성소품/알전구`)를 쿼리에 결합하여 특정 키워드(돈까스, 뷰 맛집 등)의 우선도를 재조정합니다.
4. **최종 15개 팩트 도출**: 카테고리별(의료/마트, 식당, 명소 등) 1위 1개 + 대안 2개씩 총 15개를 추립니다.
5. **AI 감성 코팅**: 위 15개 중 대표 5개를 묶어 Gemini 최신 모델(ex. 2.5 Flash Lite)에 짧은 프롬프트로 전송하여 "서사 형태"로 포장(Narration)해 화면에 띄웁니다.

## 🔍 4. API별 세부 데이터 추출 및 정제 로직 (Data Transformation Spec)

이 섹션은 1차 수집된 원시 공공데이터를 2차 정제 및 추천(Transform)하는 가장 핵심적인 내부 로직입니다. 서비스 고도화 시 계속해서 이 섹션의 조건을 수정/보완해 나가야 합니다. **모든 필터는 각 팩트의 `trustScore` 증감을 통해 15개 배열 내의 상대적 '순위'를 결정짓는 방식으로 구현**되었습니다.

### 4.1 국립중앙의료원 (응급의료기관 정보) - `[MART_HOSPITAL]`
- **수집 대상 데이터**: `dutyName`(병원명), `dutyDivName`(기관분류), `dutyTel3`(응급실전화), `wgs84Lat/Lon`(위경도), `dutyTime`(진료시간)
- **추천 및 정제 로직**:
  1. **거리 기준 (점진적 확장)**: 기본 반경 15km 필터링. 없을 시 최대 30km까지 반경을 넓히며 무조건 1개 이상의 병원을 확보.
  2. **페르소나 연계 (Kids)**: 유저 예약 정보에 미취학/초등 자녀가 있을 경우 `trustScore +50`. 병원 이름이나 설명란에 '소아/아동' 키워드가 포함되면 추가 매칭 점수 부여.

### 4.2 행정안전부 대규모점포 / 모범음식점 / 편의점 - `[MART_HOSPITAL]` & `[RESTAURANT]`
- **수집 대상 데이터**: `BPLC_NM`(사업장명), 영업상태 등.
- **추천 및 정제 로직**:
  1. **대형마트/하나로마트 분류**: 일반 마트 중 '이마트', '홈플러스', '롯데마트' 및 '농협 하나로마트'만 추출.
  2. **휴무일 방어 조건 (주말/7일 이상)**: 사용자의 캠핑 일정이 **일요일을 포함(0) 하거나 7일 이상**이면 일요일 휴무 가능성이 큰 일반 대형마트는 `trustScore -40점` 강등. 반면 규제 밖인 **'하나로마트'는 점수를 유지하여 1순위로 강제 격상**.
  3. **모범음식점 & 카카오 로컬**: 행안부 인증을 받은 식당은 기본 후보군으로 올리며, AI 주입 직전 카카오맵 API를 병렬 호출하여 최신 카테고리 태그(예: '한식', '카페' 등)로 팩트 설명을 덧칠함.
  4. **날씨 조건 반영 (식당)**: 기상청 단기예보 API 호출 결과 비/흐림 시 '탕/찌개/국밥/전골' 등 국물 라인업 `trustScore +30`. 맑은 날에는 '냉면/막국수/구이' 우선 추천.
  5. **페르소나 연계 (Kids 식당)**: 자녀 동반 페르소나이고, 식당 메타에 '돈까스/어린이/주차'가 포함되면 `trustScore +20`.

### 4.3 한국관광공사 TourAPI (축제 및 관광지) - `[SPOT]`, `[FESTIVAL]`
- **추천 및 정제 로직 (메타 분류 파싱)**:
  1. **날씨 조건부 추천**:
     - **비/흐림**: 명소 이름에 '박물관/미술관/전시관/실내' 등 키워드 포함 시 스코어 `+30` 하여 유저의 우천 방황 방지.
     - **맑음**: '자연휴양림/수목원/둘레길/야외' 등 상위 추천 `+20`.

### 4.4 한국석유공사 오피넷 (실내등유/난방) - `[MART_HOSPITAL]` (동계 한정)
- **추천 및 정제 로직**:
  1. **계절/온도 발동 조건**: 캠핑 시작일의 **월(Month)** 기준 11월~3월 동계 시즌 돌입 시 로직 발동.
  2. 반경 내 '실내등유(`C004`)' 취급 오피넷 주유소를 찾은 뒤 `trustScore +50` 폭등 부여.
  3. 마트/병원 슬롯 중 하나를 탈락시키고 이 **주유소를 강력하게 1~2위로 밀어올려** 동계 캠퍼의 생명선 확보.

### 4.1 국립중앙의료원 (응급의료기관 정보) - `[MART_HOSPITAL]`
- **수집 대상 데이터**: `dutyName`(병원명), `dutyDivName`(기관분류), `dutyTel3`(응급실전화), `wgs84Lat/Lon`(위경도), `dutyTime`(진료시간)
- **추천 및 정제 로직**:
  1. **거리 기준 (점진적 확장)**: 기본 반경 15km 필터링. 없을 시 20km -> 25km -> 최대 30km까지 반경을 넓히며 무조건 1개 이상의 병원을 확보.
  2. **기관 우선순위**: `권역응급의료센터` > `지역응급의료센터` > `응급의료기관` > `보건소` 순서 배치.
  3. **페르소나 연계**: 유저 태그에 `#영유아동반`이 있을 경우 '소아/아동' 키워드 병원에 막대한 가중치 부여.
  4. **Fallback (예외 처리)**: 야간/산지 등으로 조회가 정 안 될 경우, "119 안전신고센터 안내 및 가장 가까운 권역응급센터/보건지소 위치 검색"을 최종 텍스트로 AI에 넘김.

### 4.2 행정안전부 (대규모점포 조회) & 주변 편의점 - `[MART_HOSPITAL]`
- **수집 대상 데이터**: `BPLC_NM`(사업장명), `SITE_WHL_ADDR`(주소), `X/Y_CRD`(좌표)
- **추천 및 정제 로직**:
  1. **대형마트/하나로마트 분류**: 단순히 마트가 아니라 이름(`BPLC_NM`)에 '이마트', '홈플러스', '롯데마트' 또는 '농협 하나로마트'가 포함된 곳만 추출.
  2. **휴무일 방어 조건**: 사용자의 캠핑 일정이 "매월 2째, 4째주 일요일"을 포함하면, 휴무 확률이 80%인 이마트/홈플러스를 최하위로 강등시키고, 규제 밖인 **'하나로마트'를 1순위로 강제 격상**.
  3. **점포 부재 폴백**: 위 점포가 없을 시 인근 중대형 일반 마트/슈퍼마켓을 안내.
  4. **3순위 고정 (편의점)**: 언제든 유저가 야간에 뛸 수 있도록, 3순위에는 가장 가까운 24시간 편의점을 고정 노출.

### 4.3 식당 (백년가게/안심식당/모범음식점) - `[RESTAURANT]`
- **수집 대상 데이터**: `storNm`(가게명), `indutyNm`(업종분류), `lcLa/lcLo`(위경도), 각 기관 인증 태그.
- **추천 및 정제 로직**:
  1. **교차 검증**: 공공데이터 식당 리스트를 뽑은 뒤 카카오 Local API를 찔러 **`리뷰 수 < 10`** 인 곳은 폐업/가짜 의심으로 전면 제외.
  2. **가중치 (모범음식점 우대)**: 지자체 위생 점검을 통과한 '모범음식점' 인증 식당에 기본 가중치 부여.
  3. **날씨 조건**: 기온이 낮거나 비가 오면 '탕/찌개/전골/국밥' 가중치 상향. 화창하면 '냉면/막국수/구이' 우선 노출.
  4. **페르소나 연계**:
     - `감성/커플` 태그: 카카오 리뷰 수 상위권 중심, '분위기', '카페' 등 혼재된 곳.
     - `가성비/아이동반` 태그: 주차장 보유, 포장, 키즈메뉴(돈까스 등) 키워드 보유 식당 필터링.
  5. **신뢰도 정렬**: 최종 계산된 상위 3곳의 식당을 한 줄 요약 문구(예: "비 오는 날 어울리는 모범음식점")와 함께 AI에 전달.

### 4.4 한국관광공사 TourAPI (축제 및 관광지) - `[SPOT]`, `[FESTIVAL]`
- **수집 대상 데이터**: `title`(제목), `addr1`(주소), `mapx/mapy`(좌표), `cat3`(소분류코드), `eventstartdate/eventenddate`(행사기간)

     - 비/눈: `cat2` 분류 코드가 '박물관/미술관/전시관(A0206)' 등 **실내 시설**인 곳을 스코어 1위로 견인하여 유저의 우천 방황 방지.
     - 맑음: '자연휴양림, 포토존, 액티비티' 등 상위 추천.
  3. **페르소나 연계**: 솔로/커플은 '산책/사색/카페', 가족은 '체험장/테마파크/역사' 가중치 부여.

- **추천 및 정제 로직**:
  1. **계절/온도 발동 조건**: 기상청 기본 날씨 API 조회 시 일정 중 최저 온도가 **5도 이하**이거나 **11월~3월 동계 시즌**일 경우 발동.
  2. 반경 10km 이내 '실내등유(`C004`)' 취급 주유소 조회 및 최단거리 오름차순 정렬.
  3. 기존 3개의 마트/병원 슬롯 중 가장 우선도가 떨어지는 1개를 제거하고 이 **주유소를 강력하게 추천 삽입**하여 동계 캠퍼의 생명선 확보.

## 💾 5. 데이터 인프라스트럭처 (Phase 5 ETL Pipeline)

- **Cron Jobs (Extract & Load)**: 무거운 외부 공공데이터 API 수십 개를 유저 요청 시마다 찌르지 않습니다. 대신 Vercel Edge Function이나 Next.js 서버리스 함수로 매일/매주 단위 크론을 설정해 데이터를 먼저 당기고(Extract), 정제하여(Transform), 라온아이의 통합 `smart_plan_facts` Supabase DB 테이블에 위치 정보(Geom)와 함께 꽂아넣습니다(Load).
- **PostGIS Real-time Querying**: 사용자의 `generateSmartPlan` 호출은 외부망을 타지 않고, 내부 DB의 `ST_DWithin` 공간 함수를 써서 반경 15~30km 데이터를 초고속으로 꺼냅니다. 외부 API Rate Limit 및 IP 종속성 제약을 원천 차단하는 가장 안전한 하이브리드 캐싱 아키텍처입니다.

## 📝 5. 핵심 파일 변경/생성 지침 (Code Implementation Guide)

- **`reservation.ts`**: `Reservation` 인터페이스의 `guestDetails` 필드는 `{ adults: number, kids: { preschool: number, elementary: number, teen: number } }` 형태로 유지합니다.
- **`ReservationForm.tsx`**: 인원수 입력 폼은 반드시 위 세분화된 스키마를 수집할 수 있는 UI 컴포넌트로 구현되어야 합니다.
- **`persona.ts`**: 사용자의 과거 활동 기반으로 캠퍼 페르소나를 추출하고 태그 가중치(Decay) 로직을 관리하는 유틸리티 파일입니다.
- **`smartPlan.ts`**: UI 의존성이 없는 순수 함수 기반의 Headless Engine 파일입니다. 위 5단계 파이프라인의 핵심 로직을 담당합니다.
- **`SmartPlanProposal.tsx`**: AI 서사와 팩트 카드를 결합하여 렌더링하는 UI 컴포넌트입니다.

> **작업자 주의사항**: 이 문서는 라온아이의 '데이터 수익화' 비전과 직결된 핵심 아키텍처 문서입니다. 추가 기능을 결합할 때에도 **Zero-Cost High-Fidelity** 원칙과 **API 독립성(Hybrid Caching)** 원칙을 절대 훼손하지 마십시오.
