# Action-to-Tag Mapping Dict (행동-태그 매핑 정의서)

라온아이의 '스마트 캠핑 플랜'과 개인화 추천을 구동하기 위한 핵심 기반인 **'사용자 페르소나 추출 로직'**의 설계 규칙과 매핑 사전을 정의하는 문서입니다.

이 문서는 스마트 캠핑 플랜 엔진(`smartPlan.ts`) 구현 완료 후, 실제 사용자 데이터를 연동하기 위한 Phase 2 작업의 **단일 진실 공급원(SSOT)** 역할을 합니다.

---

## 🎯 1. 아키텍처 원칙 (Philosophy)

- **Event-Triggered Tagging**: 사용자의 모든 행동(화면 스크롤 등)을 무의미하게 감시하지 않습니다. 결제, 찜하기, 글작성 등 '의도가 명확한 명시적 행동(Strong Signal)'만을 추출하여 태그 점수로 환산합니다.
- **Controlled Vocabulary (통제된 어휘 풀)**: AI의 할루시네이션을 막고 데이터의 밀도를 높이기 위해, 앱 전체의 취향을 표현하는 마스터 태그 풀을 초기 **50개 내외로 엄격히 고정**합니다.
- **Time-Decay (시간 감가상각)**: 사용자의 취향 변화를 반영하기 위해, 오래된 행동으로 얻은 태그 점수는 서서히 감소하고 최근 행동일수록 높은 가중치를 받습니다.
- **Scoring Formula (Phase 1 적용)**: 
  `Total Score = Base Score * Signal Weight * (Recency/Condition Weights)`
  - **Strong (1.0x)**: 예약, 프로필 확정 등
  - **Medium (0.6x)**: 게시물 작성, 후원 등
  - **Weak (0.2x)**: 단순 클릭, 탐색 등

## 🏗️ 2. 시스템 데이터 아키텍처 (Technical Layers - Phase 1 완료)

데이터의 추적성과 재현성을 위해 4개의 데이터 층으로 분리하여 관리합니다.

1.  **User Action Log (`user_action_log`)**: 사용자의 모든 원시 행동 기록
    - `user_id`, `action_type`, `meta_data` (JSONB)
    - 예: `COMMUNITY_LIKE_POST`, `LBS_CLICK_BAKERY`
2.  **User Tag Ledger (`user_tag_ledger`)**: 행동이 태그 점수로 치환된 장부
    - 어떤 행동이 어떤 `TagId`에 몇 점을 기여했는지 개별 기록하여 투명성 확보
3.  **User Persona Snapshot (`user_persona_snapshot`)**: 장기적인 사용자 성향
    - 누적된 태그 점수의 총합 (Global Persona)
4.  **Trip Persona Snapshot (`trip_persona_snapshot`)**: 현재 여행의 특수 목적
    - 이번 여행(Trip) 기간에만 한시적으로 적용되는 가중치 (아이 동반 등)

## 🔗 7. API Transformation Mapping (추천 엔진 연계)

  - 응급의료기관 API: 진료과목 구분에 '소아' 또는 병원 이름에 '아동'이 포함된 기관 가중치 +50.
  - 백년가게/안심식당 API: 키즈메뉴(돈까스 등) 존재 식당 우선 추천.

  - 백년가게/안심식당 API: '분위기 좋은', '카페' 등 인스타그래머블 키워드 우선 노출.

  - 식당 및 카페 API: '애견동반', '야외좌석' 키워드가 포함된 곳만 매칭.
