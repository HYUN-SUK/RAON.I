# 라온아이 스마트 캠핑/관광 플랜 최종 특허기술 명세서 (무료 버전 Core 6대 기술)

본 문서는 라온아이(RAON.I) 스마트 여정 플랜 시스템의 실제 상용 코드 분석을 반영하여, 독창적인 기술적 과제 해결 수단을 정리한 최종 특허기술 명세서입니다. 임시명세서(가명세서) 출원 및 정식 특허 청구항 설계의 원천 컨텍스트로 활용됩니다.

---

## 1. 시스템 용어 정의 및 아키텍처 구성

*   **사용자 단말기 (User Terminal)**: 사용자가 소지하고 조작하는 모바일 단말 장치로, 사용자 정보 및 기상/LBS 데이터를 전송받아 화면에 UI를 렌더링하고, 이기종 외부 내비게이션 애플리케이션으로 경로 파라미터를 변환 및 전달하는 주체.
*   **서비스 제공 서버 (Service Provider Server)**: 백엔드 서버 시스템으로, Supabase 데이터베이스를 관리하고 외부 공공데이터/로컬 API를 백그라운드에서 동기화하며, 다단계 캐싱 스케줄러 및 AI 추론 호출을 관리하는 주체.
*   **하이브리드 여정 설계 엔진 (Hybrid Itinerary Design Engine)**: 서비스 제공 서버 내부에서 작동하며, 사전 캐싱된 목적지 정보(Track A)와 실시간 기상/경유지 데이터(Track B)를 결합하여 사용자 맞춤형 타임라인 및 AI 스토리텔링을 조립하는 핵심 연산 모듈.

## 2. 핵심 특허 기술 6대 명세

### 📌 기술 1: 리소스 제한 환경의 일일 지역 로테이션 갱신 (Quota Optimization)
*   **기술적 과제**: 외부 공공데이터/민간 로컬 API의 하루 호출 한도(Quota Limit) 한계로 인해 전국 단위의 관심지점(POI) 장소 데이터를 신선하게 유지하기 어려운 병목 문제 해결.
*   **핵심 해결 수단 (How)**:
    1.  **순환 동기화 스케줄링**: 전국 17개 광역지자체를 17일 주기로 분할하여 매일 1개 권역(도/시)씩 배치 갱신하는 로테이션 엔진 가동.
    2.  **정기 정보 갱신 및 유효성 검사**: 해당 지자체 소속 POI의 개명, 주소 변경, 폐업 및 영업 여부 등의 대량 정보를 동적 정기 동기화 및 마스터 DB 벌크 갱신 처리.
*   **데이터 흐름 (Flow)**:
    *   **입력**: 일일 스케줄러에 할당된 당일 갱신 대상 지역 행정코드 및 동기화 기준 변수.
    *   **처리**: 대상 지역 내 POI 정보를 외부 API를 통해 정기 수집하고, 마스터 DB 내의 기존 레코드 유효성 상태 업데이트 및 신규 입수 데이터 적재.
    *   **출력**: 외부 API 일일 호출 제한을 침범하지 않고 100% 최신화 완료된 지역 마스터 관심지점 데이터베이스.
*   **기술적 효과**: 일일 외부 API 트래픽 한도 위반으로 인한 서비스 차단을 방지하며, 데이터베이스 유효성을 서버 비용 부담 없이 전국 단위로 보장.

### 📌 기술 2: 다중 소스 인증 누적 및 실시간 안전 정보 융합형 스코어링 엔진
*   **기술적 과제**: 단순 거리나 리뷰 수 기준의 맛집/명소 추천을 지양하고, 기상 이변 상황 및 인원 구성에 따른 위험 요소 회피와 공인된 신뢰 지수를 종합적으로 계량화하여 안전하고 신뢰할 수 있는 장소를 추천해야 하는 과제.
*   **핵심 해결 수단 (How)**:
    1.  **다중 공인 인증 누적 합산 (Cumulative Scoring)**: 소진공 백년가게, 한국국토정보공사 LX인증맛집, 지자체 모범음식점, 농식품부 안심식당 등 서로 다른 다중 소스의 인증 데이터 매핑 시, 단순 최댓값 덮어쓰기가 아닌 점수를 누적 가산(`certBonus += 80`, `+= 30` 등)하여 복합 인증 지점의 가중치 강화.
    2.  **실시간 안전 의료 자원 모니터링**: 국립중앙의료원(NMC) 실시간 응급의료 API와 연동하여 병상 가용 정보(`hvec` - 일반병상 수, `hvs01` - 소아병상 수) 및 CT/MRI 장비 가동 정보를 실시간으로 파싱 및 스코어 가중치에 대입하여 최우선 안전지 노출 강제.
    3.  **강우 가중치 및 페르소나 매칭**: 비/눈이 내리는 강우(`isRainy`) 상황 감지 시 실내 명소(박물관, 전시관 등)에 +20점의 강우 가중치를 즉시 가산하며, 영유아 동반 시 '노키즈존' 키워드 매칭 시 -40점의 강력한 차단성 패널티 부여.
*   **데이터 흐름 (Flow)**:
    *   **입력**: 사용자가 요청한 날짜의 실시간 기상 예보 정보, 사용자 구성원 페르소나 객체, 마스터 DB 내의 검증된 POI 레코드.
    *   **처리**: `calcContextFitDeep()` 및 `buildEvidence()` 모듈을 통해 [Base 점수 + 기상 적합도 + 페르소나 안전도 + 다중 소스 누적 인증 가산 - 특정 위험 패널티]를 연산하여 최종 적합 점수(`trustScore`) 산출.
    *   **출력**: 정교하게 개인화 및 기상 상황이 반영된 안전 중심의 맞춤형 장소 추천 목록.
*   **기술적 효과**: 기상 이변 및 영유아/반려견 동반 시 발생할 수 있는 현장 사고 및 노키즈존 헛걸음 등의 실패 여정을 차단하고, 의료 비상 상황 시 실제 가용 병상을 기반으로 최단 거리 응급실을 즉시 제시하여 사용자 안전성을 혁신적으로 향상.

### 📌 기술 3: 예약 위치 기반 이중 시점 캐싱 및 카테고리별 차등 쿼터제 (Double-Timing Caching)
*   **기술적 과제**: 사용자 플랜 요청 시 실시간으로 대량의 공공/외부 API 데이터를 호출하여 처리할 때 발생하는 과도한 서버 리소스 소모 및 응답 지연(API 타임아웃) 문제를 예방하고, 조기 예약 건에 대해 실시간성을 유지하면서도 선제적으로 추천 일정을 제공해야 하는 과제.
*   **핵심 해결 수단 (How)**:
    1.  **1차 조기 적재 캐싱 (예약 다음 날 새벽)**: 사용자가 예약을 완료한 바로 다음 날 새벽에 배치 작업을 구동하여, 캠핑장 반경 20km Geo-Clustering 기반의 주변 정적 정보(명소, 식당, 대형마트 등)를 선제 수집하여 캐시 DB(`smart_plan_candidates`)에 선적재. 이를 통해 장기 예약자들에게도 즉각적인 플랜 뼈대를 제공.
    2.  **2차 정밀 동적 캐싱 (예약 3일 전 - D-3 Caching)**: 실제 체크인 정확히 3일 전(D-3) 시점에 2차 캐싱 배치 작업을 실행하여, 기상 예보, 실시간 최저가 등유 유가, 안전 가용 병원 실시간 정보 등의 동적 기상/안전/환경 변수 데이터를 재수집 및 업데이트하여 랭킹 및 팩트 카드 최종 보정.
    3.  **카테고리별 쿼터 차등 분배**: 위 1, 2차 수집 시 호출 쿼터 관리를 위해, 정보의 변경 빈도가 높은 음식점(RESTAURANT) 카테고리에는 1000개의 호출 한도(`limit_count`)를 지정하고, 변동성이 낮은 마트/명소/병원/주유소 등은 각 100개 이하로 제한하여 병렬 비동기(`Promise.all`)로 캐시 DB에 벌크 적재함.
*   **데이터 흐름 (Flow)**:
    *   **입력**: 사용자가 예약한 캠핑장의 지리적 좌표(또는 20km Geo-Cluster 중심) 데이터.
    *   **처리**: 
        *   (1차) 신규 예약 다음 날 새벽에 Geo-Clustering 기반 주변 30km POI 1차 캐싱.
        *   (2차) 체크인 D-3 시점에 실시간 기상/유가/병상 등 동적 환경 데이터 2차 수집 및 캐싱 갱신.
        *   (수집 쿼터) 각 카테고리별 호출 한도(음식점 1000, 마트 100, 병원 100 등)를 적용한 병렬 벌크 적재 실행.
    *   **출력**: 조기 일정 가용성이 보장되면서도, 체크인 시점의 실시간 정보 무결성을 반영한 캐시 데이터셋.
*   **기술적 효과**: 런타임 실시간 API 의존율을 0%로 유지하여 호출 타임아웃을 완전 방어함과 동시에, 예약 기준의 지리적 위치에서 쿼터제 벌크 캐싱을 수행하여 서버와 API 호출 트래픽 분산 달성.

### 📌 기술 4: 2단계 교차 정규화 및 UUID v5 결정론적 ID 발급 멱등화 기법
*   **기술적 과제**: 다양한 공공/로컬 데이터 소스마다 주소 정보 및 지점명 표기 형식이 상이하여, 데이터베이스에 중복 장소가 중첩 적재되고 AI 추천 시 중복 정보가 노출되는 혼선 문제 해결.
*   **핵심 해결 수단 (How)**:
    1.  **배치 1차 정규화 (UUID v5 발급)**: 주소의 지자체 명칭(SIDO)을 표준 행정명으로 일치화하고, 상호명 및 주소 내 괄호 정보/특수문자/공백을 전부 삭제한 순수 형태소 기반의 결정론적 `UUID v5` 발급.
    2.  **실시간 엔진 2차 병합 (Runtime Deduplication)**: 실시간 여정 결합 모듈(`fetchMidpointTrackB`) 내에서, 미세한 좌표 차이로 1차 정규화에서 누락되었을 수 있는 장소들을 상호명과 정제 주소의 결합 키(`name_cleanAddr`)로 2차 그룹핑하여 런타임에 중복을 제거하고, 장소 정보 및 배지를 통합 보강.
*   **데이터 흐름 (Flow)**:
    *   **입력**: 데이터 수집 파이프라인 및 실시간 룰 엔진으로 유입되는 원시 POI 레코드 세트.
    *   **처리**: `getNormalizedAddr()`, `getCleanString()`을 통한 SIDO 통합 및 문자열 클렌징 ➔ UUID v5 고유 식별자 생성(1차) ➔ 런타임 키 맵핑 기반 교차 Deduplication 및 Multi-source 배지 병합(2차).
    *   **출력**: 단일한 고유 식별자(UUID) 하에 모든 이종 정보가 단일 객체로 물리적/논리적으로 통합된 클린 POI 데이터셋.
*   **기술적 효과**: 데이터베이스 중복을 원천 제거하여 스토리지 낭비를 최소화하고, AI 생성 일정에 동일한 가게가 반복 등장하는 에러를 100% 방지하여 데이터 신뢰성 확보.

### 📌 기술 5: 동절기 자원 확보를 위한 나선형 재귀 탐색 및 3중 주소 복원 폴백 알고리즘
*   **기술적 과제**: 동절기 캠핑의 생존 자원인 등유 판매 주유소 정보의 결측 및 공공 데이터 좌표계(오피넷 TM128/KATEC) 변환 오차로 인해, 사용자가 잘못된 주소로 안내되거나 데이터 누락이 일어나는 오류 해결.
*   **핵심 해결 수단 (How)**:
    1.  **나선형 재귀 탐색 (Spiral Search)**: 동절기(11월~3월) 탐색 시, 캠핑장 중심 반경 5km부터 시작하여 가용한 주유소 5곳이 확보될 때까지 최대 30km까지 점진적으로 탐색 반경을 넓히는 오프셋 매트릭스 탐색 루프 실행.
    2.  **TM128 to WGS84 좌표 보정**: 오피넷 전용 좌표를 `proj4` 라이브러리를 통해 국제 표준 위경도로 실시간 변환하여 물리적 좌표 오차 완전 해소.
    3.  **3중 주소 힐링 체인 (Fallback Chain)**: API 응답 내 주소 데이터 결측 발생 시, [1순위 VAN_ADR ➔ 2순위 NEW_ADR ➔ 3순위 WGS84 좌표 투사 후 카카오 API 역지오코딩(`coord2address`)]의 3단계 백업 체인을 돌려 표준 도로명 주소 강제 복구 및 고유 ID 확보.
*   **데이터 흐름 (Flow)**:
    *   **입력**: 동절기 캠핑 일정의 예약 좌표 및 오피넷 실내 등유(C004 코드) API 데이터셋.
    *   **처리**: 반경별 나선형 오프셋 API 루프 호출 ➔ 좌표계 투사 보정 ➔ 주소 유무 체크 및 카카오 역지오코딩을 통한 주소 힐링.
    *   **출력**: 등유 가격 및 실주소가 완벽히 보장된 등유 주유소 추천 팩트 정보.
*   **기술적 효과**: 극동계 혹한기 캠핑 환경에서 난방용 등유 판매 지점에 대한 100% 신뢰성 있는 위치를 추적하여 사용자 조난 및 저체온증 사고를 공학적으로 방지하고 데이터 공급의 내결함성(Fault Tolerance)을 극대화.

### 📌 기술 6: AI 서사 일관성 유지형 무지연 적응형 교체 및 이기종 OS 분기형 GPS 자율 라우팅
*   **기술적 과제**: 사용자가 추천된 장소를 다른 대안 장소로 교체할 때 발생하는 API 재호출 딜레이와 AI가 제공한 전체 일정 스토리(서사)의 단절을 막고, 차량 이동 시 이기종 스마트폰 환경에서 내비게이션으로 매끄럽게 목적지를 연동해야 하는 과제.
*   **핵심 해결 수단 (How)**:
    1.  **대체안 일괄 사전 적재 (Pre-fetching JSON Tree)**: 1순위 데이터만 보내지 않고, 각 일정 단계별로 필터링을 통과한 14개의 대안 장소 리스트(Alternatives)를 최초 1회 JSON 트리 페이로드에 포함하여 전송함으로써, 단말기 단에서 무지연(Zero-Latency) 교체 상호작용 지원.
    2.  **출발지 생략형 자율 GPS 딥링크**: 외부 내비게이션 앱(카카오맵, 네이버지도) 연동 시 출발지 좌표(`sp`)를 의도적으로 제외하여, 타 앱의 캐싱된 과거 출발지로 인한 경로 오차를 제거하고 단말기의 실시간 GPS 자율성 보장.
    3.  **이기종 OS 변수 동적 맵핑 (OS Branching)**: Tmap 딥링크 구동 시 사용자 기기 OS(iOS vs Android)를 감지하여, 안드로이드 전용 `goalx/y`, `v1x/y` 파라미터와 iOS 전용 `rGoX/Y`, `rV1X/Y` 규격으로 자동 분기하여 목적지 및 경유지 소실 현상 원천 해결.
*   **데이터 흐름 (Flow)**:
    *   **입력**: 사용자의 장소 스왑(Swap) 터치 이벤트, 특정 장소의 내비게이션 경로 개시 이벤트, 사용자 단말기 OS 메타데이터.
    *   **처리**: 사전 적재된 Alternatives 노드 즉시 화면 교체 ➔ 단말 OS 판별 및 내비게이션 앱별 좌표/명칭 파라미터 규격화 맵핑 ➔ 출발지 생략형 딥링크 실행 및 2초 내 미반응 시 카카오맵 모바일 브라우저 폴백.
    *   **출력**: 화면 상에서 지연 없이 교체되는 여정과 터치 즉시 개시되는 모바일 실시간 내비게이션 경로 화면.
*   **기술적 효과**: 서버 추가 쿼리 호출 및 로딩 스피너 노출을 제로로 만들어 UI 체감 속도를 대폭 높이고, 경로 탐색의 오차율을 최소화하여 실제 주행 시의 안정적인 차량 연계성 보장.
