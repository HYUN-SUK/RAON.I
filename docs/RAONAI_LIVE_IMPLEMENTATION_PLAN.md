# 스마트플랜 LIVE - 타임라인 기반 구현 계획 (MVP)

무료 버전(카테고리 리스트)과 유료 버전(시간대별 타임라인)의 구조를 완전히 분리하고, 타임라인 위에서 5대 실시간 대처(Live Adaptation) 기능이 동작하도록 설계된 아키텍처 및 구현 계획입니다.

## ⚠️ 상태 및 리뷰 현황 (Status)

*   **진행 상태**: 기획 및 아키텍처 초안 승인 완료. 다음 세션에서 Phase 1(코어 아키텍처)부터 실제 코드 개발 진입 예정.
*   **결정 사항**:
    *   캠핑 vs 일반 여행 모드 분기점은 '페르소나 선택 직후'로 확정.
    *   타임라인 상태 관리는 프론트엔드 전역 상태(Zustand)와 영구 저장소(DB/Local Storage)를 동기화하여 구현.
    *   유료 결제(Paywall) 로직은 기능 완벽 구현 후 최종 단계에서 미들웨어 형태로 덧붙임.

---

## 🛠 Proposed Architecture & Changes

### 0. 코어 아키텍처: 시간대별 타임라인 생성기 (Foundation)
유료 버전의 핵심 판을 깝니다.
*   **AI (Gemini) 프롬프트 분리**: 기존 프롬프트는 놔두고, `PRO` 용 프롬프트를 신설합니다. 
    *   **입력 변수**: 여행 일수, 캠핑/일반 모드, 페르소나.
    *   **출력 형식 (JSON)**: `[ { time: "09:00", type: "activity", title: "수목원 산책", duration_mins: 90, location_id: "...", phone: "..." } ]` 형태의 엄격한 시계열 배열.
*   **UI (Frontend)**: 시간의 흐름이 수직 또는 수평으로 보이는 타임라인(Gantt 차트 또는 Stepper 형태) UI. 각 블록에는 `[출발/시작]` 버튼이 존재.

### 1. 타임 리밸런싱 (Dynamic Time-Shifter)
데이터의 불확실성을 유저 경험(UX)으로 극복하는 핵심 로직입니다.
*   **시간 재계산**: 특정 타임블록에서 지연 발생 시 하위 일정들의 시간을 일괄 재계산.
*   **영업시간 대응 로직 (UX 승리)**:
    1. 카카오/네이버 로컬 API의 전화번호 데이터와 카테고리별 '기본 마감 시간' 활용.
    2. 재계산된 도착 시간이 마감 시간에 임박하면 빨간색 팝업 노출: *"영업이 마감되었을 수 있습니다. 출발 전 확인해보세요 📞"*
    3. 팝업 터치 시 스마트폰 기본 전화 앱으로 연결.
    4. 통화 종료 후 앱 복귀 시 *"영업이 끝났나요? 다른 곳으로 대체하기"* 버튼(Swap) 제공.

### 2. 스마트 핏스탑 (Smart Pitstop)
*   **검색 로직**: 
    1. 유저가 자체 카테고리(주유소 등) 선택 또는 커스텀 키워드(화장실 등) 직접 입력.
    2. 자체 DB 조회 후 없을 경우, 카카오 로컬 API(현재 GPS 기준 경로 내 반경 검색) 실시간 호출.
    3. 자체 필터링(별점, 리뷰 수)을 거쳐 상위 6개 노출 및 타임라인에 Insert.

### 3. 원탭 테마 스위처 & 트래픽 디톡스 (Theme Switcher)
*   **데이터 선별 로직**: (개발 시점 심층 논의 과제)
    *   실시간 대처의 빠른 속도를 위해 LLM 필터링은 지양.
    *   자체 DB(11만 개)에서 '실내', '휴식' 등을 어떻게 빠르고 정확하게 쿼리해올 것인지(카테고리 매칭, 키워드 검색, 혹은 배치 작업을 통한 사전 태깅 등) 구체적인 기술 검토 후 개발 진행.

### 4. SOS 메디컬 레이더 (Live Medical SOS)
*   **검색 로직**: 
    1. 현재 GPS 기준 반경 내 검색.
    2. 공공데이터(NMC API - 국립중앙의료원) 실시간 호출 (가장 정확).
    3. NMC API 응답 실패 시 Fallback으로 카카오 로컬 API "야간약국" 검색 결과 노출.

### 5. Co-Op 플래너 (가족 투표기)
*   **Logic**: 
    1. AI가 타임라인을 먼저 1차로 완전 생성.
    2. 각 타임블록 카드에서 일행 초대(링크 공유) 가능.
    3. 일행은 각 장소의 **'대체 리스트(Swap List)'**를 열어 인당 최대 3개까지 '좋아요(하트)' 투표.
    4. Supabase Realtime을 통해 좋아요 수를 실시간 합산.
    5. 득표 1위 장소로 메인 카드를 실시간 자동 스왑(Auto-Swap) 및 재정렬하며 장소명 옆에 그룹용 득표수 뱃지 노출.

## 🚀 개발 우선순위 (Phasing)

본 문서를 바탕으로 다음 세션부터 순차적으로 개발을 진행합니다.

**Phase 1 (The Foundation)**: 타임라인 UI 및 PRO AI 프롬프트 설계
*   목표: 카테고리 뷰가 아닌 시간대별 JSON 배열을 프론트엔드에 렌더링하고, 캠핑/여행 모드 분리.

**Phase 2 (The Core)**: 타임 리밸런싱 로직 구현
*   목표: 타임라인 시간 재계산 및 '전화 연결 -> 스왑' UX 흐름 구현.

**Phase 3 (Live Adaptations)**: 핏스탑, 스위처, SOS 레이더 부착
*   목표: 완성된 타임라인 위에 현장 대처용 액션 버튼과 검색 연동(NMC, 카카오 로컬 API).

**Phase 4 (Social Pre-planning)**: Co-Op 플래너
*   목표: 완성된 타임라인 위에 Supabase Realtime을 활용한 실시간 대체 리스트 투표 로직 연동.
