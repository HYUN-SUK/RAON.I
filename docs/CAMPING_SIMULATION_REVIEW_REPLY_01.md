### 1-2. Capacitor 환경의 공유/저장
- Capacitor WebView에서는 Web Share API의 **파일 공유가 동작하지 않는 경우가 많음** → `@capacitor/share` + `@capacitor/filesystem` 플러그인으로 처리 권장 (웹 브라우저 접속 시에만 Web Share API 사용).

### 1-3. WebGL 안정성 기본 장치 (저사양 대응)

- 화면 이탈/모달 종료 시 geometry·material·texture `dispose()` 및 `gl.forceContextLoss()` 처리
- `webglcontextlost` 이벤트 감지 시 **Konva 2D 탑뷰로 자동 전환** + 안내 문구
- 첫 진입 시 간단한 성능 측정(프레임 시간) → 그림자 해상도·파티클 수 자동 하향

### 1-4. 폰 스캔(Polycam/Scaniverse) 일정
- P0에는 불필요. **실측 치수만으로 진행**하고 스캔 메시는 P1 이후 적용.
- 도입 전 무료 플랜의 **glTF/GLB 내보내기 가능 여부**를 확인 (앱별 무료 제한 상이).
- 적용 시 웹 최적화 목표: 사이트당 메시 2MB 이하, Draco/meshopt 압축.

### 1-5. 2단계 모드 분리 + 자동 갱신
개발팀의 [태양/그늘 모드] ↔ [날씨/바람 풀 모드] 분리에 아래를 추가해 주세요.

## 2. P0 범위 의견

제안 범위 `[철수네 1개 사이트 + 터널형 절차적 메시 1종 + SunCalc 태양/그림자 + 3일 예보 타임랩스 + 1탭 결과 카드]`에 **동의**하며, 아래 2가지를 추가해 주세요.

1. **철수네 주변 능선 고도각 (16방위 horizon profile)**
   - 산 그림자에 따른 실제 일출·일몰 시각 차이가 이 기능의 핵심 가치이므로 P0에서 반드시 보여줘야 합니다.
   - 대표님이 스마트폰 경사계(기울기) 앱으로 16방위 능선 각도를 측정해 입력 (약 10분 소요 예상).
2. **현장 검증 1회 (품질 판정 기준)**
   - 맑은 날 같은 시각(예: 15:00, 17:00)에 실제 사이트 그늘 사진 vs 시뮬레이션 화면을 비교.
   - 그늘 경계·산 그림자 진입 시각이 대략 일치하면(±15분 목표) P1 진행 근거로 사용.

## 3. 회전 각도 채점(Scoring) 공식 초안

> 모든 수치는 **초기값**입니다. 사이트별·계절별 피드백으로 보정할 수 있도록 상수는 설정 파일(또는 DB)로 분리해 주세요.

### 3-1. 후보 생성
- 0°~345°, **15° 간격 24방향** (방향 = 텐트 입구가 향하는 방위)
- 위치는 P0에서 사이트 중앙 고정, P1부터 위치 후보(그리드)까지 확장

### 3-2. 하드 제약 (먼저 제외)
- 텐트·타프·스트링 영역(스트링 여유 1m 포함)이 사이트 경계를 벗어남 → 제외
- 나무·차량·데크 등 장애물과 겹침 → 제외
- 남은 후보가 없으면 "이 사이트에는 텐트 크기가 커요" 안내 (사이트 맞춤 경고 자체가 가치)

### 3-3. 총점
```
score(θ) = 100 − 100 × ( w_sun·Ŝ_sun(θ) + w_wind·Ŝ_wind(θ) + w_rain·Ŝ_rain(θ) ) + bonus(θ)
```
- `Ŝ` = 각 항목 원점수를 24방향 내에서 0~1 min-max 정규화한 값 (항목 간 단위 차이 제거)
- `bonus(θ)`: 캠장 추천 방향(`owner_tips`)과 ±15° 이내면 +5, 입구가 진입로/주차 쪽을 향하면 +2

### 3-4. 항목별 원점수 (샘플 간격 10~15분, 체크인~체크아웃 합산)

**① 햇빛 S_sun** (입구·거실 영역 일사 노출)
```
Σ_t  sin(alt_t) × (1 − cloud_t) × max(0, cos(az_t − θ)) × season_t
```
- `alt_t ≤ horizon(az_t)` (능선 아래) 또는 고도 ≤ 0 이면 0
- `cloud_t`: SKY 1=0, 3=0.5, 4=0.8 (기상청 하늘상태 매핑)
- `season_t`: 여름(최고기온 ≥ 28℃) 12~17시 ×1.5 / 겨울(최고기온 ≤ 10℃) 오전 일사는 **음수 가중(-0.5, 가점 효과)**

**② 바람 S_wind** (풍하중 ∝ 풍속²)
```
Σ_t  wsd_t² × k_shape(φ_t)      φ_t = 풍향(vec_t) − θ 의 상대각
```
- 터널형: `k = sin²(φ)` (측풍 취약) + 입구로 바람이 들이침 `max(0, cos(φ))` × 0.5 추가
- 돔형: `k = max(0, cos(φ))` (입구 정면풍만 불리)
- 리빙쉘·캐빈: 터널형 계수 × 0.8 / 티피: 0.3 (방향성 약함)
- 타프: 낮은 쪽을 풍상측에 두는 각도 계산은 별도 (P1)
- 야간(수면 시간) 포함, 가중치 동일

**③ 비 S_rain**
```
Σ_t  (pop_t / 100) × max(pcp_t, 0.5) × max(0, cos(φ_t))
  + (입구가 경사 하향 방향 ±45° 이내이면 고정 페널티 1.0 × 강수 시간 수)
```

### 3-5. 계절별 가중치 (w_sun / w_wind / w_rain)
| 조건 | w_sun | w_wind | w_rain |
|---|---|---|---|
| 여름 (6~8월 또는 최고기온 ≥ 28℃) | 0.5 | 0.3 | 0.2 |
| 봄·가을 | 0.3 | 0.5 | 0.2 |
| 겨울 (12~2월 또는 최저기온 ≤ 0℃) | 0.2 | 0.6 | 0.2 |
| **오버라이드**: 기간 중 최대 풍속 ≥ 7 m/s | 0.15 | 0.7 | 0.15 |
| 태양/그늘 모드 (D-3 이전, 바람 예보 없음) | 1.0 | 0 | 0 |

### 3-6. 출력 규칙
- 1위 방향 추천. **1·2위 점수 차 ≤ 5점이면 두 방향 모두 제시**하고 장단점 한 줄씩 (예: "A: 오후 그늘 좋음 / B: 바람에 더 안정적")
- 팩 보강 위치: 기간 중 풍하중이 가장 큰 시간대의 풍상측 팩·스트링 표시
- 결과 카드 문구는 SSOT 톤(따뜻함·담백함)으로, 숫자는 최소화

### 3-7. 피드백 기반 보정 (P2)
- 체크아웃 후 1탭 피드백(좋았음 / 햇빛 불편 / 바람 불편 / 비 불편)을 `pitch_simulations.feedback`에 저장
- 사이트별 가중치·지형 풍향 보정값을 점진 조정하는 구조로 설계 (P0에서는 스키마만 고려)
