# RAON.I 신규 기능 인수인계서: 가상 피칭 & 캠핑 시뮬레이션 (Pitching Simulator)

- 작성일: 2026-09-27
- 작성 배경: 대표(캠장)와 Claude의 기획 검토 세션 결과를 개발 AI에게 전달하기 위한 문서
- 문서 성격: **기획·검토 확정본이 아님.** 개발 AI는 이 문서를 먼저 검토하고, 의문점·리스크·대안을 대표에게 보고한 뒤 승인받고 개발에 착수할 것.

## 1. 무엇을 만드는가 (한 문단 요약)

캠퍼가 캠핑장 사이트에서 **텐트·타프를 어느 방향, 어느 위치에 칠지**를 출발 전에 미리 정할 수 있도록, 실제 사이트를 3D로 재현한 가상 공간에 자신의 텐트·타프를 배치하고, **캠핑 기간(예: 2박 3일, 72시간)의 태양 이동·그림자·기온·바람·비를 약 30초 타임랩스로 시뮬레이션**한 뒤, 결과를 근거로 **추천 입구 방향, 보강할 팩 위치, 주의할 시간대, 준비물**을 안내하는 기능.

## 2. 왜 필요한가 (사용자 문제)

- 캠퍼는 매번 현장에서 "텐트 입구를 어디로 둘지, 사이트 안에 다 들어갈지, 해와 바람을 어떻게 피할지"를 고민한다.
- 그래서 캠장에게 "여기는 어떻게 쳐요?"라고 자주 묻고, 캠장은 텐트 종류·크기를 듣고 "이 사이트는 보통 이렇게 치세요, 오후엔 이쪽에서 바람 불어요"라고 안내한다.
- 이 **캠장의 현장 조언을 데이터 + 시뮬레이션으로 앱에서 미리 제공**하는 것이 목표.

기대 효과
- 여름: 해를 최대한 피하는 방향으로 배치 재구성
- 비 예보: 언제 비가 오는지 보고 배수·타프 각도 대비
- 강풍 예보: 어느 쪽 팩·스트링을 보강할지 사전 준비

## 3. 반드시 지켜야 할 조건 (대표 요구사항)

| # | 조건 | 의미 |
|---|---|---|
| C1 | **비용 0원 또는 극소** | 소규모 캠핑장 1인 운영. 구축·운영 모두 무료 티어 중심. 유료 3D 지도 API(구글 Photorealistic 3D Tiles 등) 의존 금지 |
| C2 | **높은 시각 품질** | "실제와 비슷한" 사이트 3D + 고품질 텐트/타프. 조잡하면 사용자가 안 씀 |
| C3 | **현장과 비슷한 시뮬레이션** | 실제 예보·실제 태양 궤적·실제 지형 반영. 결과가 현장에서 실효적이어야 함 |
| C4 | **버튼 한 번** | 사용자가 질문을 입력할 필요 없이, 예약 정보만으로 자동 실행 |
| C5 | **찾기 쉬운 위치** | 스마트플랜 실패 교훈(아래 5.3) 반영. 필요한 순간에 눈앞에 버튼이 있어야 함 |

## 4. 핵심 설계 원칙 (검토 세션 합의 사항)

1. **물리 시뮬레이션(CFD 등)이 아니다.** "예보 데이터 + 천문 계산 + 지형 데이터를 3D로 재생 + 규칙 기반 판단" 구조로 만든다. 사용자 체감은 시뮬레이션, 실제 연산은 가볍게.
2. **태양·그림자 = 가장 정확하고 가장 가치 있는 영역.** 좌표·날짜만 있으면 분 단위로 정확. 핵심 셀링포인트로 삼는다.
3. **바람 = 시각 연출 + 규칙.** 풍향 입자·타프 흔들림으로 보여주고, 판단은 텐트 형태별 규칙표로 한다.
4. **처음엔 라온아이 캠핑장 8개 사이트만 대상.** 범용 캠핑장 지원은 이후 확장. 캠장이 직접 실측한 데이터로 최고 품질을 먼저 증명.
5. **진짜 자산은 코드가 아니라 데이터.** 사이트별 실측 데이터·캠장 노하우·사용자 피드백을 구조화해 쌓는 데 신경 쓸 것. (AI가 발전해도 이 데이터는 복제 불가. 향후 외부 AI가 호출할 수 있는 API/MCP 형태로 제공할 가능성까지 고려해 데이터 스키마를 깔끔하게 설계)
6. **결과는 한 장 카드로 담백하게.** 3D 재생은 원하는 사람만. 결론(입구 방향·보강 팩·준비물)이 먼저.

### 5.3 스마트플랜의 교훈 (`RAON.I_스마트플랜_진단보고서.docx` 요약)
- 실사용 순수 유저 5명, 전원 1회성 사용, 이후 재사용 0.
- 원인: 기능 품질이 아니라 **접근성·재참여 설계 부재** (하단 네비 없음, 접힌 아코디언 뒤에 숨음, 선행 절차 필요, 열리는 시점을 알려주는 푸시 없음).
- → 본 기능은 **예약 완료 화면 / 다가오는 예약 카드 / D-1 푸시**에서 바로 실행되게 설계할 것.

### 5.4 알려진 주의점
- `api/weather/route.ts`의 base_date 계산이 서버 로컬 시간(`new Date()`) 기준. Vercel(UTC)에서 KST 자정~09시 사이 날짜 오류 가능성 검토 필요.
- 기상청 단기예보는 **약 D+3(발표 시점에 따라 최대 72시간 전후)까지**만 시간별 풍향·풍속 제공. 그 이후는 중기예보(일 단위, 바람 없음) → 시뮬레이션 신뢰 구간은 **출발 3일 전부터**. 그 전에는 "태양·그림자만 정확, 날씨는 평년/예비값"으로 명시.
- 기상청 WSD는 10m 높이 평균풍속. 순간돌풍 정보 없음 → Open-Meteo `wind_gusts_10m` 보조 사용 검토 (현재 폴백 URL에는 gust 미포함).

## 6. 기능 명세 (초안)

### 6.1 사용자 흐름
1. **진입**: 예약 완료 화면 / 다가오는 예약 카드의 [🏕️ 내 사이트 미리 쳐보기] 버튼, 또는 D-1 푸시 "내일 영희네 사이트 날씨 시뮬레이션이 준비됐어요"
2. **장비 선택** (최초 1회, 이후 저장): 텐트 형태 선택 → 치수 입력 또는 인기 모델 프리셋 선택 / 타프 형태·치수
3. **자동 추천 배치**: 시스템이 최적 방향으로 텐트·타프를 먼저 배치해서 보여줌
4. **직접 조정**: 드래그로 이동, 회전 핸들로 방향 변경 → 점수 즉시 갱신 (예: "오후 햇빛 노출 2.5시간 → 40분")
5. **▶ 재생**: 체크인~체크아웃 전체를 약 30초 타임랩스로 재생
6. **결과 카드**: 추천 입구 방향 / 보강할 팩(3D에 빨간 표시) / 주의 시간대 / 준비물
7. (후속) 체크아웃 후 "추천대로 쳐보니 어땠나요?" 1탭 피드백

### 6.2 입력 데이터

| 구분 | 항목 | 출처 | 비용 |
|---|---|---|---|
| 위치 | 캠핑장 좌표, 사이트별 좌표 | 캠장 입력 (관리자 화면) | 0 |
| 일정 | 체크인/체크아웃 | 예약 데이터 | 0 |
| 태양 | 시간별 방위각·고도 | `suncalc` 라이브러리 계산 | 0 |
| 날씨 | 시간별 기온·습도·풍향·풍속·강수형태·강수확률·하늘상태 | 기존 `/api/weather` (기상청 + Open-Meteo) | 0 |
| 주변 지형 | 방위별 산 능선 높이각 (horizon profile) | **MVP: 캠장 실측** (스마트폰 경사계 앱으로 16방위 측정) / 확장: 국토지리정보원 DEM | 0 |
| 사이트 | 가로·세로(m), 사이트 기준 방위, 바닥재, 경사 방향·정도, 나무·데크·주차·전기함·배수로 위치 | 캠장 실측 입력 | 0 |
| 장비 | 텐트/타프 형태, 길이·폭·높이, 입구 위치 | 사용자 입력 / 프리셋 DB | 0 |
| 노하우 | "이 사이트는 보통 이렇게 쳐요", 골바람 방향 등 | 캠장 메모 | 0 |

### 6.3 데이터 모델 초안 (Supabase, 개발 AI가 검토·수정할 것)

```sql
-- 사이트 지오메트리 (sites 테이블 확장 또는 별도 테이블)
create table site_geometry (
  site_id text primary key references sites(id),
  lat double precision not null,
  lng double precision not null,
  width_m numeric not null,          -- 사이트 가로
  depth_m numeric not null,          -- 사이트 세로
  bearing_deg numeric not null,      -- 사이트 '앞쪽(진입로)'이 향하는 방위 (0=북, 90=동)
  ground_type text,                  -- gravel | deck | grass | soil
  slope_deg numeric default 0,
  slope_dir_deg numeric,             -- 낮아지는 방향
  horizon_profile jsonb,             -- [{az:0, alt:12.5}, {az:22.5, alt:15}, ...] 16방위 능선 고도각
  obstacles jsonb,                   -- [{type:'tree', x, y, radius, height}, {type:'car', ...}, {type:'deck', ...}]
  local_wind_note text,              -- 예: '오후엔 계곡 방향(남서)에서 골바람'
  owner_tips text,                   -- 캠장 노하우
  updated_at timestamptz default now()
);

-- 사용자 장비
create table user_gear (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id),
  kind text not null,                -- tent | tarp
  shape text not null,               -- tunnel | dome | tipi | livingshell | cabin | hexa_tarp | recta_tarp | wing_tarp
  preset_id text,                    -- 프리셋 모델 선택 시
  length_m numeric, width_m numeric, height_m numeric,
  door_side text,                    -- front | side | both
  nickname text,
  created_at timestamptz default now()
);

-- 텐트 프리셋 (인기 모델 치수 DB)
create table gear_presets (
  id text primary key, brand text, model text, kind text, shape text,
  length_m numeric, width_m numeric, height_m numeric, door_side text
);

-- 시뮬레이션 결과 & 피드백 (데이터 자산)
create table pitch_simulations (
  id uuid primary key default gen_random_uuid(),
  user_id uuid, reservation_id uuid, site_id text,
  placement jsonb,                   -- 텐트/타프 위치·회전
  weather_snapshot jsonb,            -- 사용한 예보 스냅샷
  result jsonb,                      -- 점수·경고·추천
  feedback jsonb,                    -- 체크아웃 후 피드백
  created_at timestamptz default now()
);
```

RLS: `site_geometry`, `gear_presets`는 전체 읽기 / 관리자만 쓰기. `user_gear`, `pitch_simulations`는 본인만.

### 6.4 시뮬레이션 엔진 (클라이언트 계산, 서버 비용 0)

1. **시간축**: 체크인 14:00 ~ 체크아웃 11:00 (사이트 정책 확인), 10~15분 간격 샘플.
2. **태양**: 각 시점의 방위각·고도 (`suncalc`). 고도가 `horizon_profile`의 해당 방위 능선 고도보다 낮으면 "산 그림자 속"으로 처리 → 일출·일몰이 실제보다 늦고/빠른 효과가 자연스럽게 반영됨.
3. **그림자/일사**: 텐트 입구 면·타프 아래 영역·거실 공간이 햇빛에 노출되는 시간 계산 (Three.js 그림자 + 간단한 광선 교차 판정).
4. **바람**: 예보 풍향(vec)·풍속(wsd)을 시간 보간. `local_wind_note`/지형 보정 규칙 적용 (MVP는 캠장이 입력한 보정값 사용).
5. **판단 규칙표 (초기값, 튜닝 필요)**:
   - 터널형: 좁은 후면(낮은 쪽)을 주풍향으로. 측풍에 취약 → 측풍 예보 시 측면 스트링 보강 경고
   - 돔형: 입구를 바람 반대(풍하)로
   - 타프: 낮은 쪽을 풍상측으로, 비 예보 시 한쪽을 낮춰 배수 경사
   - 풍속 기준(10m 예보 기준, 초기값): 4 m/s 이상 스트링 전부 체결 권장 / 7 m/s 이상 타프 높이 낮추기·팩 보강 / 10 m/s 이상 타프 철수 권고
   - 여름(기온 28℃ 이상): 오후 서향 일사 회피 가중치↑ / 겨울: 아침 동향 일사 선호, 최저기온 기반 난방 준비물
   - 비: 강수 시간대 표시, 사이트 경사 낮은 쪽에 입구·짐 배치 금지
6. **점수화**: 방향 0~345°를 15° 단위로 돌려가며 (일사 노출, 풍하중, 사이트 경계 침범 여부, 장애물 충돌) 가중합 → 최고 점수 방향을 자동 추천.
7. **출력**: 추천 방향, 팩 보강 위치(주풍향 기준 풍상측 팩·스트링), 시간대별 경고 타임라인, 준비물 리스트.

### 6.5 3D 렌더링 (품질 요구 C2)
- 엔진: Three.js + React Three Fiber + drei. `dynamic(..., { ssr: false })`로 분리.
- **사이트**: 캠장 입력값으로 절차적 생성 (바닥 재질: 파쇄석/데크/잔디 PBR 텍스처, 나무·차량·데크 오브젝트). 주변 산은 horizon_profile로 원경 능선 메시 생성.
  - 확장안: 무료 폰 스캔 앱(Polycam, Scaniverse 등)으로 사이트를 스캔해 glTF 실사 모델로 교체.
- **텐트/타프**: 브랜드별 실제 3D 모델은 구하기 어렵고 라이선스 문제 → **형태별 파라메트릭 생성** (치수 입력 → 코드로 메시 생성). 반투명 원단 재질, 폴 라인, 스트링, 팩, 부드러운 그림자까지 표현해 "실루엣" 이상의 품질 목표.
- **환경 연출**: 시간대별 하늘색·조명 색온도, 태양 방향광 + 그림자, 구름/비 파티클, 바람 파티클 및 타프 흔들림(풍속 비례).
- **타임라인 UI**: 하단 스크러버 + 경고 마커(예: "토 14시 강풍 8m/s", "일 03시 4℃", "일 10시 강수 60%").
- **성능 목표**: 중급 안드로이드 TWA에서 30fps. 그림자 해상도·파티클 수 자동 하향. 저사양·WebGL 미지원 시 **Konva 2D 탑뷰 폴백** (해 그림자 방향·바람 화살표).
- **공유**: 결과 30초 영상/이미지 내보내기 (홍보 효과 기대, 단 특허 출원 후 공개).

### 6.6 관리자(캠장) 화면
- `admin/sites/[id]`에 "시뮬레이션 데이터" 탭 추가: 좌표(지도 클릭), 크기, 방위(나침반 입력), 바닥재, 경사, 장애물 배치(2D 탑뷰 에디터, Konva 활용), 16방위 능선 고도각, 캠장 노하우 메모.

## 7. 특허 관련 (개발 일정에 영향)
- 대표는 **개발이 거의 끝나고 공개 전에 특허 출원**을 검토 중.
- 공개(출시·홍보영상·베타 공개) **전** 출원이 원칙. 핵심 처리 흐름이 확정되면 먼저 출원하고, 1년 내 국내우선권으로 개선 내용 보강하는 방식 검토.
- 출원 후보가 될 수 있는 기술 흐름: 사이트 지오메트리·방위·능선 고도각 + 사용자 장비 치수 + 예약 기간 태양 궤적 + 격자 예보 → 시간대별 일사 노출·풍하중 계산 → 배치 방향 점수화·추천 → 풍상측 보강 위치 표시.
- 개발 AI 요청: 개발 중 핵심 알고리즘의 **입력·처리 단계·출력**을 별도 문서(`docs/pitching_sim_invention_notes.md`)로 기록해 변리사 상담 자료로 쓸 수 있게 할 것.
- 개발 기간 중 기능은 관리자 전용 / 피처 플래그 비공개 유지.

## 9. 비용 추정
- 라이브러리: three / R3F / drei / suncalc 모두 MIT 무료
- 날씨: 기상청 공공데이터(무료) + 기존 격자 캐시 → 같은 사이트 사용자 수와 무관하게 격자당 수 시간에 1회 호출
- 시뮬레이션 연산: 전부 클라이언트(사용자 폰)에서 수행 → 서버 비용 0
- 3D 에셋: 절차적 생성 + 무료 PBR 텍스처(CC0, 예: Poly Haven, ambientCG)
- 호스팅/DB: 기존 Vercel·Supabase 무료/현 요금제 범위
- **예상 추가 운영비: 초기 사실상 0원**
