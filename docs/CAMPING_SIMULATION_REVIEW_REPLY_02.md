## 2. 텐트·타프 3D 시각 품질 기준

### 2-1. 목표 수준
- **"모바일 게임 중상급 ~ 건축 시각화 앱" 수준의 깔끔한 3D 디오라마(미니어처) 스타일.**
- 포토리얼리즘은 목표가 아님. 어설픈 사실감(uncanny)은 오히려 품질이 낮아 보이므로 **정돈된 스타일라이즈드 리얼리즘**을 지향. 이것이 저사양 기기 성능에도 유리.
- 대표님 요구: "사용자가 보기 좋아야 한다." → 품질 판단은 P0 실기기 확인으로 결정.

### 2-2. 절차적(Procedural) 텐트/타프 필수 표현 요소
| 요소 | 요구사항 |
|---|---|
| 형태·비율 | 사용자 입력 치수(가로/세로/높이) 정확 반영. 터널형 아치, 돔 곡면, 리빙쉘·캐빈 벽면, 티피 원뿔, 타프 처짐(catenary) 곡선 자연스럽게 |
| 구조 디테일 | 폴 라인(원단 위 볼록 라인), 원단 이음선, 입구 지퍼 라인/롤업 표현, 스트링(가이라인), 팩 |
| 원단 재질 | 무광 원단 질감, 얇은 원단의 **은은한 빛 투과(translucency 근사)**, 가장자리 약간의 처짐 |
| 색상 | 사용자 선택 (아이보리, 샌드, 카키, 올리브, 그레이, 차콜 등 6~8종) → `user_gear`에 `color` 필드 추가 |
| 바람 연출 | 원단 물리 시뮬레이션은 제외. 풍속 비례 **버텍스 셰이더 흔들림**(타프 > 텐트 순으로 크게) |

### 2-3. 품질을 좌우하는 4대 체크포인트 (P0 판정 기준)
1. **부드러운 그림자**: 하드 섀도우 금지. PCF Soft / `drei`의 `SoftShadows` 또는 `AccumulativeShadows`(정지 시) + 접지 그림자(ContactShadows) 조합 검토
2. **바닥·주변 품질**: 파쇄석/잔디/데크 바닥 PBR 텍스처(CC0: Poly Haven, ambientCG), 주변 나무는 저폴리 + 알파 잎 텍스처로 자연스럽게
3. **시간대별 하늘·조명**: drei `Sky` 또는 그라데이션 하늘 + 태양 고도에 따른 색온도 변화(아침 주황 → 낮 백색 → 노을 → 밤 청색) + 앰비언트 오클루전(경량 SSAO 또는 베이크드 AO)
4. **첫 카메라 구도**: 진입 즉시 보기 좋은 3/4 부감 시점(약 35~45°)으로 텐트·타프·사이트 전체가 한 화면에. 이후 자유 회전/줌

### 2-4. 한계 (대표님께 공유된 내용)
- 브랜드 로고, 원단 미세 주름, 사실적인 원단 펄럭임 물리는 구현하지 않음
- 실물과 "동일한" 외형이 아니라 "형태·크기·색이 같은 내 텐트"로 인지되는 것이 목표

## 3. 장애물 위치 입력 방식 (좌표 입력 불필요)

### 3-1. 측정 기준: "사이트 기준 모서리 + 거리"
- 사이트의 **앞쪽 왼쪽 모서리**(진입로에서 사이트를 바라볼 때 왼쪽 앞)를 원점 (0,0)으로 정의
- x축 = 오른쪽(가로 방향), y축 = 안쪽(세로 방향), 단위 m
- 예시: "원점에서 오른쪽 2m, 안쪽 1m에 나무 (높이 약 6m, 줄기 굵기 30cm, 수관 반경 약 2.5m)"
- 사이트 밖이지만 그늘을 만드는 나무는 음수 좌표·사이트 범위 밖 좌표 허용

### 3-2. 관리자 입력 UI: 격자 드래그 에디터 (P1, Konva 활용)
- `admin/sites/[id]` → "시뮬레이션 데이터" 탭
- 사이트 가로·세로 입력 시 **실척 격자판(1m 격자)** 자동 생성
- 아이콘 팔레트(나무, 차량, 데크, 전기함, 수도, 배수로, 화로대 위치, 펜스)를 **드래그해 배치** → 내부적으로 사이트 로컬 좌표(m)로 저장
- 아이콘별 속성: 나무(높이, 수관 반경), 차량(크기 프리셋), 데크(가로·세로·높이)
- 사이트 사진(사이트별 3장)을 격자판 옆에 참고용으로 표시
- 사이트 로컬 좌표 → 3D 월드 좌표 변환은 `bearing_deg` 기준 회전으로 처리

### 3-3. P0 임시 방식
- 철수네는 대표님이 줄자로 잰 값을 3-1 형식의 텍스트/사진 메모로 전달 → 개발팀이 JSON으로 하드코딩

### 3-4. 스키마 반영
`site_geometry.obstacles` (jsonb) 예시:
```json
[
  { "type": "tree", "x": 2.0, "y": 1.0, "height": 6.0, "trunk_d": 0.3, "crown_r": 2.5 },
  { "type": "car",  "x": 0.5, "y": -1.5, "w": 1.9, "l": 4.8, "rot": 0 },
  { "type": "deck", "x": 3.0, "y": 4.0, "w": 3.0, "l": 3.0, "h": 0.3 }
]
```

## 4. 16방위 능선 고도각(horizon profile) 자동 산출

### 4-1. 배경
- 캠장도 능선 각도는 알 수 없음 → **무료 지형 고도(DEM) 데이터로 자동 계산**. 사이트 좌표만 있으면 됨.
- 사이트별 좌표를 각각 사용해 8개 사이트 모두 개별 산출.

### 4-2. 데이터 소스 (모두 무료)
| 소스 | 해상도 | 용도 | 비고 |
|---|---|---|---|
| **Open-Meteo Elevation API** | 약 90m (Copernicus DEM GLO-90) | 원거리 능선 (수백 m ~ 수 km) | 앱에서 이미 날씨 폴백으로 쓰는 서비스. 요청당 다수 좌표 조회 가능 — 호출 한도·약관은 개발팀이 확인 |
| **국토지리정보원 수치표고모델(DEM)** | 5m | 근거리 산자락 정밀 계산 | 국토정보플랫폼 회원가입 후 다운로드. 캠핑장 주변 타일만 받아 전처리 |

권장: P0는 Open-Meteo로 빠르게 산출 → 정확도 부족 시 국토지리정보원 5m DEM으로 교체/보정.

### 4-3. 산출 알고리즘
```
입력: 사이트 좌표(lat, lng), 사이트 지면 고도 h0 (DEM 조회), 관측 높이 +1.5m
for az in [0, 22.5, 45, ..., 337.5]  (16방위; 정밀도 필요 시 36방위 권장)
    for d in 거리 샘플 (50m ~ 5km, 근거리 촘촘히: 50m 간격 → 원거리 200m 간격)
        p = 좌표에서 방위 az로 거리 d 떨어진 지점
        h = DEM(p)
        angle = atan2(h - (h0 + 1.5), d)   # 지구 곡률 보정: h -= d² / (2·6371000) (5km 이내 영향 작음)
    horizon[az] = max(angle)  (음수면 0)
출력: [{az, alt}] → site_geometry.horizon_profile
```
- **1회성 배치 계산**: 사이트 등록/좌표 변경 시에만 실행해 DB 저장 (런타임 API 호출 없음, 비용 0)
- 방위 사이 값은 선형 보간해 태양 방위별 능선 고도를 구함
- 시각화: 3D 원경에 이 프로파일로 능선 실루엣 메시 생성 → 산 그림자 진입 시각이 화면과 계산에 동시 반영

### 4-4. 한계와 보완
- **나무는 DEM에 포함되지 않음** → 사이트 인근 나무 그늘은 3장 장애물 입력으로 처리
- DEM 오차·근거리 지형 오차 가능 → **현장 검증**: PeakFinder, Sun Surveyor 등 AR 앱으로 실제 능선·태양 경로를 확인하거나, 회신 #1의 "현장 그늘 사진 비교(±15분 목표)"로 검증
- 관리자 화면에서 방위별 능선 각도를 **수동 보정**할 수 있는 입력란 제공 (P1)

## 5. 현장 실측 가이드 (대표님용, 개발팀은 입력 UI 설계 시 반영)

| 항목 | 방법 | 주의사항 |
|---|---|---|
| 가로·세로 | 줄자 또는 스마트폰 측정 앱 | 사이트 경계(팩을 박을 수 있는 범위) 기준 |
| 전면 방위 | 나침반 앱으로 사이트 앞쪽(진입로 쪽)이 향하는 방향 | **반드시 "진북(True North)" 설정 사용.** 한국은 자북이 진북보다 서쪽으로 약 8~9° 편차. 앱이 자북만 지원하면 개발팀이 편각 보정 처리 (입력 UI에 진북/자북 선택 필드) |
| 경사 | 스마트폰 수평계(기울기) 앱을 바닥에 놓고 가로·세로 방향 각 1회 | 낮아지는 방향 함께 기록 |
| 장애물 | 3-1 기준(앞쪽 왼쪽 모서리 원점)으로 줄자 측정, 또는 사진에 표시 | 나무는 높이·수관 크기 대략값 |
| 사이트 좌표 | 사이트 중앙에서 지도 앱 위치 확인 (관리자 화면 지도 클릭 입력 예정) | 능선 자동 계산의 입력값 |
| 능선 각도 | **측정 불필요** (4장 자동 계산) | 원하면 AR 앱으로 검증만 |
