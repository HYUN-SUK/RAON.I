# 특허 임시명세서 첨부용 기술설명서

## 1. 발명의 명칭
멱등적 장소 데이터 정규화 및 단말기 센서 융합에 기반한 AI 적응형 여정 설계 및 온디바이스 실시간 캠핑 환경 제어 시스템 및 방법
*(System and Method for AI-Based Adaptive Itinerary Design and On-Device Real-Time Camping Environment Control Based on Idempotent Place Data Normalization and User Terminal Sensor Fusion)*

---

## 2. 시스템 구성원 및 용어 정의

본 발명을 설명하기 위한 시스템 구성 요소들의 정의는 다음과 같이 통일하여 정의한다.

1.  **사용자 단말기 (User Terminal)**: 사용자가 휴대하는 모바일 기기로서, 위치 정보(GPS 위경도) 및 내장 센서(가속도, 자이로, 마이크) 원시 데이터를 수집하고, 피칭 나침반 UI 렌더링, 초고주파 출력 및 이기종 외부 내비게이션 애플리케이션으로 경로 파라미터를 맵핑 및 전달하는 주체.
2.  **서비스 제공 서버 (Service Provider Server)**: 클라우드 기반 백엔드 시스템으로, 정적/동적 마스터 데이터베이스를 관리하고, 외부 공공/민간 API를 분할 주기식으로 스케줄링하여 동기화하며, 사전 캐싱 및 AI 생성 연산 서비스를 사용자 단말기에 제공하는 주체.
3.  **하이브리드 여정 설계 엔진 (Hybrid Itinerary Design Engine)**: 서비스 제공 서버와 사용자 단말기에 분산 탑재된 연산 모듈로서, 사전 적재된 배치 캐시 데이터(Track A)와 실시간 경로/기상 정보(Track B), 그리고 실시간 노드 삽입/삭제 시 전체 스케줄을 재조정하는 물리적 1차 룰 엔진이 융합된 제어 엔진.
4.  **캠핑 안전 환경 관리 모듈 (Camping Safety Module)**: 기상 데이터 폴링, 단말의 충격 임계값 필터링 연산, 해충 기피용 주파수 음파 합성 및 웹소켓(Supabase Realtime) 이중 통신 경보를 수행하는 제어 모듈.

---

## 3. 기존 기술의 문제점

1.  **AI 여정 설계의 시간/공간적 오류 및 API 비용 과다**:
    종래의 생성형 AI 기반 여행 추천 시스템은 AI 모델 특유의 환각(Hallucination) 오류로 인해 실재하지 않거나 폐업한 장소를 추천하고, 지도 데이터와 연계되지 않아 하루의 시간 제약 내에서 물리적으로 방문이 불가능한 꼬인 일정을 도출함. 또한, 사용자가 일정을 변경하거나 장소를 스왑(Swap)할 때마다 고비용의 LLM API를 반복적으로 직접 호출함으로써 서버 통신 비용 및 리소스 소모가 지수적으로 증가하는 문제가 있음.
2.  **체류형 야외 캠핑 환경에서의 현장 안전 및 피칭 제어 기술 부재**:
    캠핑은 정해진 장소에 텐트를 구축하고 머무르는 **체류형 여정**으로 정적인 일정표의 상업적 가치가 극히 낮음. 사용자가 캠핑장에 도착했을 때 해의 일주 방향이나 시간대별 바람(풍향/풍속)의 벡터 변화를 파악하기 어려워 폴대 붕괴 등의 사고가 발생하며, 야간 취침 시의 도난이나 야생동물 침입, 사계절 독충/해충(진드기, 모기) 등 텐트 내부의 생존 및 안전에 직결된 환경 제어 솔루션이 부재한 상황임.

### [파트 A] 데이터 파이프라인 및 실시간 룰 엔진 (무료 버전)

#### 1. 리소스 제한 환경의 일일 지역 로테이션 갱신 (Quota Optimization)
서비스 제공 서버는 외부 공공데이터 API의 일일 호출 한도(Quota Limit) 내에서 마스터 데이터의 신선도를 영구 보장하기 위해, 전국 17개 광역지자체를 17일 주기로 분할하여 매일 1개 도/시씩 순환하여 해당 지역 마스터 POI의 유효성과 폐업 여부 등을 정기적으로 동기화 및 대량 갱신하는 **순환 동기화 알고리즘**을 수행한다.

#### 2. 다중 소스 인증 누적 및 실시간 안전 정보 융합형 스코어링 엔진
하이브리드 여정 설계 엔진은 맛집/명소 추천 시 다음과 같은 수식에 기반하여 적합도 점수(`trustScore`)를 연산한다.

$$Final\ Score = Base\ Score(50) + ContextFit(0\sim100) + certBonus(인증) + tierBonus(티어) + distScore(거리) - Penalty$$

*   **인증 점수 누적 합산 (Cumulative Scoring)**: 소진공 백년가게(+80), LX인증맛집(+80), 모범음식점(+30), 안심식당(+20) 등 복수의 기관에서 공인받은 장소는 단순 최댓값이 아닌 모든 가점을 누적 합산하여 신뢰 등급을 조율함.
*   **실시간 안전 의료 자원 융합**: 국립중앙의료원(NMC) 실시간 응급의료 API와 연동하여 가용 가능한 실시간 병상 정보(일반병상 `hvec`, 소아병상 `hvs01`) 및 CT/MRI 가동 유무 데이터를 파싱해 `HOSPITAL` 점수에 실시간으로 대입하고 안전 가중치를 부여함.
*   **강우 가중치 및 페르소나 가점**: 기상 예보 상 강우(`isRainy`) 상황 감지 시 실내 명소에 +20점의 강우 가중치를 즉시 합산하며, 영유아 동반 시 '노키즈존' 키워드와 매핑되면 -40점의 강력한 차단성 패널티를 부여함.

#### 3. 예약 위치 기반 이중 시점 캐싱 및 카테고리별 차등 쿼터제 (Double-Timing Caching)
실시간 플랜 생성 요청 시의 서버 지연(Latency)을 차단하고 서버의 호출 트래픽을 분산하기 위해, **사용자가 예약한 타겟 캠핑장의 지리적 좌표(또는 20km Geo-Cluster 중심)를 기준으로 주변 30km 반경의 데이터를 캐싱**하는 2단계 파이프라인을 가동한다.
*   **1차 조기 캐싱 (예약 다음 날 새벽)**: 신규 예약 완료 다음 날 새벽에 배치 작업을 기동하여, 캠핑장 반경 주변의 비교적 정적인 데이터(명소, 식당, 대형마트)를 1차로 수집해 캐시 DB(`smart_plan_candidates`)에 선적재하여 장기 예약자의 조기 조회를 보장함.
*   **2차 정밀 동적 캐싱 (예약 3일 전)**: 투숙 3일 전(D-3)에 실시간 기상 예보, 실시간 주유 가격, 안전 가용 병원 등 변동성이 높은 환경 데이터를 재수집 및 갱신해 랭킹을 최종 보정함.
*   **카테고리별 쿼터 차등 분배**: 위 1, 2차 수집 시 호출 쿼터 관리를 위해, 정보의 변경 빈도가 높은 음식점(RESTAURANT) 카테고리에는 1000개의 호출 한도(`limit_count`)를 지정하고, 변동성이 낮은 마트/명소/병원/주유소 등은 각 100개 이하로 제한하여 병렬 비동기(`Promise.all`)로 캐시 DB에 벌크 적재함.

#### 4. 2단계 교차 정규화 및 UUID v5 결정론적 ID 발급 멱등화 기법
서로 다른 API 소스 간 장소 중복을 방지하기 위해 이중 멱등화 필터를 적용한다.
*   **1차 정규화 (UUID v5 발급)**: 주소의 지자체 명칭(SIDO)을 표준 행정명으로 통일화하고, 상호명 및 주소 내 괄호 정보, 특수문자, 모든 공백을 제거한 형태소 문자열에 기반해 결정론적인 UUID v5를 발급하여 마스터 DB에 적재함.
*   **2차 정규화 (런타임 멱등화)**: 실시간 여정 결합 모듈(`fetchMidpointTrackB`) 내에서, 미세한 좌표 오차로 인해 UUID가 다르게 발급되었을 수 있는 장소들을 상호명과 정제 주소의 결합 키(`name_cleanAddr`)로 2차 그룹핑하여 런타임에 중복 노드를 병합하고 원천 소스 및 배지 정보를 통합함.

#### 5. 동절기 자원 확보를 위한 나선형 재귀 탐색 및 3중 주소 복원 폴백 알고리즘
극동계 난방용 등유 주유소 확보를 위해 다음의 알고리즘을 수행한다.
*   **나선형 재귀 탐색 (Spiral Search)**: 캠핑장 중심 반경 5km부터 시작하여 등유 판매 주유소 5곳이 확보될 때까지 최대 30km까지 점진적으로 탐색 반경을 넓히는 오프셋 매트릭스 탐색 루프 실행.
*   **좌표 및 주소 보정**: 오피넷 API 특유의 TM128 좌표를 `proj4` 라이브러리를 통해 표준 WGS84 좌표계로 정밀 변환하고, 주소값 결측 발생 시 [1순위 VAN_ADR ➔ 2순위 NEW_ADR ➔ 3순위 WGS84 좌표 기반 카카오 API 역지오코딩(`coord2address`)]의 3단계 백업 체인을 돌려 고유 ID 및 도로명 주소를 자가 치유함.

#### 6. AI 서사 일관성 유지형 무지연 적응형 교체 및 이기종 OS 분기형 GPS 자율 라우팅
*   **대체안 사전 적재 (Pre-fetching)**: 1순위 추천 노드(Primary)와 함께 각 단계별 대안 장소 리스트(Alternatives, 최대 14개 후보)를 최초 1회 JSON 페이로드에 포함하여 단말기에 일괄 전송함으로써, 단말기 상에서 무지연(Zero-Latency) 교체 상호작용 지원.
*   **GPS 자율성 및 OS 분기형 딥링크**: 외부 내비게이션(카카오맵, 네이버지도) 연동 시 출발지 좌표(`sp`)를 생략하여 과거 출발지 매핑 오차를 차단하고, Tmap 연동 시 사용자 기기 OS(iOS vs Android)를 감지하여, 안드로이드 전용 `goalx/y`, `v1x/y` 파라미터와 iOS 전용 `rGoX/Y`, `rV1X/Y` 규격으로 동적 분기하여 목적지 유실 오류를 제거함.

### [파트 B] 프로(Pro) 버전 하이브리드 엔진 및 단말기 제어

#### 7. RAG-Rule 하이브리드 여정 수정 및 동적 타임-밸런싱 (Dynamic Time-balancing) 엔진
사용자의 일정 변경 요청에 대응하여 서버의 LLM 토큰 비용을 방어하고 물리적인 이동 실현 가능성을 100% 보장하는 하이브리드 처리 엔진이다.

```
[사용자 단말기] ── (실시간 장소 추가/삭제 요청) ──> [1차 물리적 룰 엔진]
                                                           │
                                                           ├──> [시간/거리 연동 물리 제약 검증 (Constraint Guard)]
                                                           │      └─ 불가 시: 단말기에 경고 반환 (LLM 미호출)
                                                           │      └─ 가능 시: 가용 시간 압축 및 오프셋 시프트
                                                           │
                                                           ▼ (정리된 JSON 뼈대 전송)
                                                    [LLM (Gemini)] ➔ [최종 수정 서사 출력]
```

*   **실시간 노드 삽입 및 삭제 연산**:
    여행 도중 사용자가 실시간 검색을 통해 특정 카테고리(식당, 마트, 명소, 병원, 주유소, 축제)의 장소를 기존 일정 중간에 삽입하거나 삭제를 요청할 경우, 서비스 제공 서버의 **1차 물리적 룰 엔진**이 즉시 작동한다.
*   **가용 시간 압축 및 동적 오프셋 시프트 (Time-balancing)**:
    1.  **시간 축 검증**: 신규 장소 삽입 시, 룰 엔진은 현재 단말의 LBS 위치 및 현재 시각을 기준으로 기존 일정 블록들의 시간대를 파악함.
    2.  **시간 압축 알고리즘**: 타이트한 일정 내에 빈 시간 슬롯이 부족한 경우, 기존 일정들의 체류 시간(`duration_mins`)에 일정 비율(예: 15%~25%)의 압축률을 적용해 가용 시간 영역을 확보함.
    3.  **지리적 오프셋 재계산**: 신규 POI 좌표를 기준으로 이전 노드와 다음 노드 간의 물리적 이동 거리 및 소요 시간(`travel_mins`)을 실시간 재연산하여 전체 타임라인의 타임스탬프를 동적으로 시프트(Shift) 조정함.
*   **물리적 제약 가드 (Constraint Guard)**:
    이동 소요 시간의 합이 남은 하루 가용 시간(최종 귀가 시간 제약)을 초과하는 지리적 불가능 상황이 감지되면, **LLM 호출을 차단하고 단말기에 "이동 시간 부족으로 일정 추가 불가"라는 경고 메시지를 즉시 반환**하여 연산 비용을 아낌.
*   **하이브리드 서사 합성**:
    룰 엔진에 의해 100% 물리적으로 정돈 완료된 JSON 일정 뼈대 데이터만을 LLM에 전달하여 최종 스토리텔링 및 연결 문구만 매끄럽게 합성하게 함으로써, LLM 토큰의 중복 연산 비용을 획기적으로 차단함.

#### 8. 온디바이스 피칭 디렉터 나침반 (Pitching Director Compass)
외부 기상/천체 API 호출 비용을 방지하고 네트워크 음영 지역에서도 가동할 수 있도록 설계된 온디바이스 기하학 연산 장치이다.
*   **온디바이스 천체 일주각 연산**:
    사용자 단말기의 실시간 GPS 위경도와 날짜 정보를 입력받아, 일출, 남중, 일몰의 방위각과 고도를 단말 내부 오프라인 상태에서 삼각함수 공식(SunCalc알고리즘)으로 실시간 수학적 계산 수행.
*   **통합 일정 슬라이더 및 풍향 벡터 다중 가시화**:
    2박 3일(0~72시간) 캠핑 전체 일정을 조절하는 슬라이더 스크롤러 이벤트를 수집하여, 선택한 시간대의 기상 바람 데이터(풍속, 풍향)를 나침반 축상에 동적으로 매핑함. 바람의 주행 방향 변화(북풍 ➔ 서풍 ➔ 남풍 등)를 나타내는 반투명 화살표의 회전각과 풍속 세기를 3D 나침반 레이아웃 상에 겹쳐 동적 가시화 및 자동 재생(Play) 파노라마 시각화 처리.

#### 9. LIVE 윈드 세이프티 (Wind Safety)
*   서비스 제공 서버에서 기상청 API를 15분 간격으로 추적하여 풍속 6m/s 또는 순간풍속 10m/s 이상 돌풍 감지 시 사용자 단말기에 푸시 경보 발송.
*   사용자 단말기에 사전에 등록된 텐트의 기하학적 구조(돔형, 리빙쉘형, 타프)와 캠핑 바닥재(데크, 파쇄석, 마사토)의 인장 계수 수치 모델을 불러와 바람이 불어오는 직격 방향에 대한 벡터 대항력을 연산, 메인 폴대 및 스트링의 물리 결속/보강 위치(예: 30cm 장팩 깊이 체결 권고 등) 가이드를 제공함.

#### 10. LIVE 텐트 보안관 (Tent Sentry)
*   사용자 단말기의 3축 가속도계 및 자이로스코프 센서의 원시 데이터(DeviceMotionEvent)를 실시간 수집.
*   **5초 영점 조절 (Calibration)**: 활성화 시점부터 5초간 기저 바람 흔들림 및 환경 백그라운드 노이즈 데시벨을 측정하여 영점 오프셋을 획득, 오작동을 필터링함.
*   **이중 경보 메커니즘**: 측정 영점 대비 충격 변화량($\Delta G > 0.15G$)이 0.3초 이상 지속 시 침입으로 확정하여, [1차 로컬 대응: 단말기 스피커로 초고주파 16kHz~18kHz 및 경보음을 최대 음량으로 송출하고 카메라 LED 플래시 점멸 ➔ 2차 원격 대응: Supabase Realtime 웹소켓 채널을 통해 외부에 있는 일행의 단말기로 즉시 침입 위험 알림을 전송].

#### 11. LIVE 독충 및 해충 가드 (Pest & Insect Guard)
*   실시간 기온/습도, 산림 분포 정보 및 질병관리청 살인진드기 활성 모델 공식을 결합하여 캠핑장 내 **[독충 위험 지수]** 연산.
*   사용자 단말기 스피커를 통해 모기 및 해충이 기피하는 천적 잠자리의 날갯짓 음파 대역(16kHz~18kHz)을 동적으로 주파수 합성(Frequency Synthesis)하여 송출함으로써 해충 진입 장벽을 형성하고, 독충 물림 식별 가이드 및 응급처치 애니메이션 연계 가시화.

## 5. 단계별 데이터 흐름 (Overall Flow)

```
[Step 1: 데이터 수집 및 정규화 (1차 멱등화)]
   - daily-region-sync.mjs 가동 ➔ 지자체 순환 갱신 ➔ 주소 정규화 및 UUID v5 마스터 DB 벌크 적재

[Step 2: 예약 트리거 2단계 시차 사전 캐싱 (Track A)]
   - (1차 캐싱) 신규 예약 다음 날 새벽 ➔ Geo-Clustering 기반 20km 반경 내 주변 데이터 DB 선적재
   - (2차 캐싱) 체크인 3일 전(D-3) ➔ 실시간 기상 예보, 실시간 최저가 등유 유가, 안전 병원 등 동적 데이터 2차 캐싱 갱신
   - (캐싱 쿼터) 수집 시 카테고리별 차등 Quota(음식점 1000, 마트/명소/의료/주유소 각 100) 부여하여 병렬 적재

[Step 3: 실시간 여정 결합 및 2차 멱등화 (Track B)]
   - 사용자 플랜 요청 ➔ 캐싱 DB 조회 ➔ name_cleanAddr & allSources 배열 기반 실시간 2차 중복 제거
   - LBS 목적지/출발지 좌표 ➔ 카카오 API 기반 중간지점 도로망 정밀 산출

[Step 4: 하이브리드 점수 산출 및 RAG 전처리]
   - 기상청 날씨 + 페르소나 센서 수집 ➔ ContextFit 연산 (우천 가점 + 소아과/반려견/보양식 안전 가산)
   - 백년가게, LX인증 누적 합산 스코어링 + NMC 실시간 가용 병상 정보 가중치 융합
   - 1차 물리적 룰 엔진 이동 스케줄 뼈대 갱신 ➔ Alternatives 장소 목록 묶음 JSON 구성

[Step 5: 여정 도중 실시간 노드 변경 및 시간-거리 재계산]
   - 여정 도중 실시간 장소 검색 및 추가/삭제 요청 ➔ 1차 물리적 룰 엔진 기동
   - Haversine 거리 및 이동 시간 실시간 재계산 ➔ 일정 가용 시간 압축 및 전체 타임라인 오프셋 Shift
   - 물리적 이동 가능 여부 판단(Constraint Guard) ➔ 통과 시에만 LLM 최종 수정 서사 합성

[Step 6: 단말기 센서 융합 및 실시간 환경 제어 (Pro 기능)]
   - SunCalc 오프라인 연산 + 0-72시간 풍향 벡터 나침반 가시화
   - DeviceMotionEvent 3축 데이터 스트리밍 ➔ 5초 영점 필터 ➔ \Delta G 임계값 비교 침입 탐지
   - 쯔쯔가무시 활성 지수 연산 및 16~18kHz 초고주파 해충 퇴치 음파 연속 출력

[Step 7: 길찾기 인계 및 안전 대피]
   - 내비게이션 요청 ➔ iOS/Android 단말 OS 감지 ➔ goalx/y 분기 변수 매핑 ➔ sp 출발지 생략 딥링크 실행
```

## 6. 기대되는 기술적 효과 (Technical Effects)

1.  **서버 연산 리소스 및 토큰 비용의 획기적 절약**:
    사용자의 수시적인 일정 변경 및 스왑 시, 1차 물리적 룰 엔진(Constraint Guard)이 지리적 실현 가능성을 먼저 검증하고 스케줄을 압축 재배열하므로, 무작위적인 LLM 호출에 따른 API 토큰 낭비를 50% 이상 방지하고 레이턴시를 최소화함.
2.  **데이터 통신 단절(Zero-network) 상태에서의 서비스 연속성**:
    천체 일주각 연산 및 해충 퇴치용 주파수 음파 출력을 모바일 단말기 단에서 온디바이스 오프라인 수학식으로 100% 실행함으로써, 깊은 산속이나 음영 지역에서의 배터리 소모율을 획기적으로 낮추고 통신 장애 복원력을 확보함.
3.  **데이터 공급 인프라의 내결함성 극대화**:
    API 주소 결측 발생 시 3중 역지오코딩 폴백 체인과 TM128 좌표계 실시간 맵 투사를 수행하여, 전국 단위 장소 매칭 및 AI 타임라인 생성의 에러 발생률을 0%에 가깝게 차단하고 데이터 무결성을 보장함.
4.  **보안/침입 방지 장치의 오보율의 획기적 개선**:
    바람에 흔들리는 텐트의 물리적 불규칙 진동(노이즈)을 5초 간의 기저 대역 노이즈 캔슬링(영점 조절)을 통해 걸러내어 가속도 센서 작동의 신뢰도를 극대화함.
